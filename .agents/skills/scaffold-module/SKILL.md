# ODH Module Operator Guide

This project is a template for building ODH Module Operators — standalone
Kubernetes controllers that implement the ODH Module Operator Contract.

## Architecture

The module operator externalizes what was previously a `ComponentHandler`
inside the monolithic ODH Operator. It reconciles a cluster-scoped singleton
Module CR using the same action pipeline infrastructure from the operator's
`pkg/` packages.

### Dependencies

| Library | Import path | Purpose |
|---|---|---|
| opendatahub-operator | `github.com/opendatahub-io/opendatahub-operator/v2` | ReconcilerFor builder, action pipeline (deploy, gc, kustomize, helm, releases, deployments), conditions manager, status constants, api/common types |
| cobra | `github.com/spf13/cobra` | CLI subcommand structure |
| viper | `github.com/spf13/viper` | Config from flags and environment variables |

The `go.mod` uses a `replace` directive pointing to a fork branch
(`lburgazzoli/opendatahub-operator@internal-const`) that moves status
constants from `internal/` to `pkg/` to make them importable.

### PlatformObject Contract

Every Module CR must implement `common.PlatformObject` from the operator's
`api/common` package:

```go
type PlatformObject interface {
    client.Object
    WithStatus          // GetStatus() *Status
    ConditionsAccessor   // GetConditions() / SetConditions()
}
```

The status embeds `common.Status` (Phase, Conditions, ObservedGeneration) and
`common.ComponentReleaseStatus` (Releases). Mandatory conditions:

- `Ready` — top-level aggregate, orchestrator checks this
- `ProvisioningSucceeded` — manifest application result
- `DeploymentsAvailable` — deployment readiness

### Action Pipeline

The controller uses `reconciler.ReconcilerFor` to build a sequential action
pipeline. Each action is a `func(context.Context, *ReconciliationRequest) error`.

Standard pipeline for a module operator:

```
initialize -> releases -> kustomize -> deploy -> deployments -> gc
```

| Action | Package | Purpose |
|---|---|---|
| `initialize` | local | Sets manifest paths on `rr.Manifests` |
| `releases.NewAction()` | `pkg/controller/actions/status/releases` | Populates release info in status |
| `kustomize.NewAction()` | `pkg/controller/actions/render/kustomize` | Renders kustomize manifests to `rr.Resources` |
| `deploy.NewAction()` | `pkg/controller/actions/deploy` | Applies resources to the cluster via SSA |
| `deployments.NewAction()` | `pkg/controller/actions/status/deployments` | Checks deployment readiness, sets conditions |
| `gc.NewAction()` | `pkg/controller/actions/gc` | Garbage-collects orphaned resources |

Custom actions can be inserted anywhere in the pipeline via `WithAction()`.

## Project Structure

```
api/<group>/<version>/           API types (CRD structs, PlatformObject impl)
cmd/main.go                      Cobra root command
cmd/operator/operator.go         Operator subcommand (manager setup)
cmd/chartgen/                    Chart generator subcommand
internal/controller/<group>/     Controllers (one subdirectory per kind)
pkg/cache/                       Cache transform (StripUnusedFields)
config/chart/                    Helm chart (generated by chartgen subcommand)
config/crd/bases/                Generated CRD YAMLs (DO NOT EDIT)
config/rbac/role.yaml            Generated RBAC (DO NOT EDIT)
config/manager/                  Deployment + ConfigMap manifests
config/samples/                  Example CRs
hack/scripts/                    Build/release automation scripts (kind-setup.sh)
```

## Key Files

| File | Purpose |
|---|---|
| `api/components/v1alpha1/mymodule_types.go` | Module CR: empty spec, PlatformObject status, CEL singleton validation |
| `cmd/operator/operator.go` | Manager setup: scheme, cache config (StripUnusedFields), client config, viper flags |
| `internal/controller/components/mymodule/mymodule_controller.go` | ReconcilerFor builder with action pipeline |
| `internal/controller/components/mymodule/mymodule_controller_actions.go` | Initialize action (sets manifest paths) |
| `internal/controller/components/mymodule/mymodule_support.go` | Constants, condition types, manifestPath helper |
| `pkg/cache/transform.go` | StripUnusedFields — removes managedFields + last-applied-configuration |
| `config/manager/configmap.yaml` | Pre-populated controller config ConfigMap |
| `cmd/chartgen/` | Helm chart generator subcommand (reads kustomize YAML from stdin, writes chart) |

## Common Workflows

### Add a new module kind

1. Create the API:
   ```bash
   go run sigs.k8s.io/kubebuilder/v4@latest create api \
     --group components --version v1alpha1 --kind NewModule --namespaced=false
   ```

2. Replace the scaffolded types in `api/components/v1alpha1/newmodule_types.go`:
   - Empty spec struct
   - Status embedding `common.Status` + `common.ComponentReleaseStatus`
   - Implement `PlatformObject`: `GetStatus()`, `GetConditions()`, `SetConditions()`
   - Add CEL singleton validation: `self.metadata.name == 'default-newmodule'`
   - Add print columns for Ready status and Reason

3. Create the controller directory `internal/controller/components/newmodule/` with:
   - `newmodule_controller.go` — ReconcilerFor builder (copy from mymodule, rename)
   - `newmodule_controller_actions.go` — initialize action
   - `newmodule_support.go` — constants and manifestPath helper

4. Register the controller in `cmd/operator/operator.go`:
   ```go
   import "github.com/.../internal/controller/components/newmodule"
   // In run():
   if err := newmodule.NewReconciler(cmd.Context(), mgr); err != nil { ... }
   ```

5. Regenerate:
   ```bash
   make manifests generate build test
   ```

### Add a custom action to the pipeline

Insert a new action function between existing pipeline steps:

```go
reconciler.ReconcilerFor(mgr, &v1alpha1.MyModule{}).
    WithAction(initialize).
    WithAction(releases.NewAction()).
    WithAction(myCustomAction).          // added here
    WithAction(kustomize.NewAction(...)).
    // ...
```

The action receives a `*ReconciliationRequest` with:
- `rr.Instance` — the Module CR being reconciled
- `rr.Resources` — accumulated unstructured resources (after render)
- `rr.Manifests` — manifest paths (before render)
- `rr.Conditions` — conditions manager
- `rr.Client` — k8s client

### Add owned resources

Add `.Owns()` calls to the ReconcilerFor builder for any resource type the
controller creates. This registers a watch so changes to owned resources
trigger reconciliation:

```go
reconciler.ReconcilerFor(mgr, &v1alpha1.MyModule{}).
    Owns(&appsv1.Deployment{}, reconciler.WithPredicates(predicates.DefaultDeploymentPredicate)).
    Owns(&corev1.Service{}).
    Owns(&corev1.Secret{}).
    // ...
```

Add corresponding RBAC markers on the controller file:

```go
// +kubebuilder:rbac:groups="",resources=secrets,verbs=get;list;watch;create;update;patch;delete
```

### Regenerate Helm chart

```bash
make helm
```

This pipes kustomize output through the `chartgen` subcommand:
`kustomize build config/default | manager chartgen --output config/chart`

The chart is generated with Helm template injection. Template files are named
by GVK: `<group>_<version>_<kind>.yaml`. CRDs are in `templates/` alongside
other resources.

The `chartgen` subcommand also generates `values.yaml` (defaults extracted from
the Deployment), `values.schema.json` (from Go struct reflection), and
`Chart.yaml` (preserved if it already exists).

### Add module-specific configuration

The module operator follows a two-layer config model:

- **CR spec** — reconciliation target state (what the controller reconciles toward).
  Add fields to `MyModuleSpec` in `mymodule_types.go`.

- **ConfigMap** — controller process config (flags, log levels, feature gates).
  Edit `config/manager/configmap.yaml`. The ConfigMap is volume-mounted at
  `/etc/controller/config` and read via `CONTROLLER_CONFIGURATION_PATH`.

### Update platform overlay paths

Edit `ManifestsSourcePath` in `mymodule_support.go` to map platform variants
to kustomize overlay directories. The `initialize` action uses this to set
the correct manifest path for the current platform.

## Cobra CLI Structure

```
opendatahub-module-operator
  operator              Start the module operator
  chartgen              Generate Helm chart from kustomize YAML on stdin
```

Add new subcommands by creating `cmd/<name>/<name>.go` with a `NewCommand()`
function, then register in `cmd/main.go` via `root.AddCommand()`.

### Operator Flags

| Flag | Env Var | Default | Purpose |
|---|---|---|---|
| `--metrics-addr` | `OPERATOR_METRICS_ADDR` | `:8080` | Metrics bind address |
| `--health-probe-addr` | `OPERATOR_HEALTH_PROBE_ADDR` | `:8081` | Health probe bind address |
| `--pprof-addr` | `OPERATOR_PPROF_ADDR` | (empty) | Pprof bind address |
| `--leader-elect` | `OPERATOR_LEADER_ELECT` | `true` | Enable leader election |
| `--leader-election-id` | `OPERATOR_LEADER_ELECTION_ID` | `...-lock` | Lock name |

## Singleton Pattern

Module CRs are cluster-scoped singletons enforced by a CEL validation rule:

```go
// +kubebuilder:validation:XValidation:rule="self.metadata.name == 'default-mymodule'",message="MyModule name must be default-mymodule"
```

The API server rejects any CR creation with a name other than `default-mymodule`.

## Cache Configuration

The manager uses a custom cache transform (`pkg/cache.StripUnusedFields()`) that
removes `managedFields` and `kubectl.kubernetes.io/last-applied-configuration`
from all cached objects. Both are unnecessary when using server-side apply and
waste memory in the informer cache.

## Container Image

Uses `Containerfile` (not Dockerfile) with `podman` (not docker):

- **Builder stage**: `golang:1.25`
- **Runtime stage**: `registry.access.redhat.com/ubi10/ubi-micro:latest`

```bash
make container-build IMG=<registry>/<name>:<tag>
make container-push IMG=<registry>/<name>:<tag>
```

The `CONTAINER_TOOL` variable defaults to `podman`. Override with
`CONTAINER_TOOL=docker` if needed.

## Testing

Uses standard controller-runtime envtest with Ginkgo:

```bash
make test
```

Test suite is at `internal/controller/components/suite_test.go`. CRD path
for envtest points to `config/crd/bases/`.
